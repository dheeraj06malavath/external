# Q1. Docker Compose – Online Boutique Store (25 Marks)

## 1. Docker Compose YAML file

Create a file named `docker-compose.yml`.

yaml

```yaml

version: '3.8'

services:
  mysql:
    image: mysql:8.0
    container_name: boutique-mysql
    restart: always
    environment:
      MYSQL_ROOT_PASSWORD: root123
      MYSQL_DATABASE: boutique_db
      MYSQL_USER: boutique_user
      MYSQL_PASSWORD: boutique123
    ports:
      - "3306:3306"
    volumes:
      - mysql_data:/var/lib/mysql
    networks:
      - boutique-network

  tomcat:
    image: tomcat:9.0
    container_name: boutique-tomcat
    restart: always
    ports:
      - "8080:8080"
    depends_on:
      - mysql
    networks:
      - boutique-network

volumes:
  mysql_data:

networks:
  boutique-network:
    driver: bridge
```

## 2. Explanation of YAML file

| Configuration | Description |
| --- | --- |
| `mysql:8.0` | MySQL database image |
| `tomcat:9.0` | Tomcat web server image |
| `3306:3306` | Exposes MySQL port |
| `8080:8080` | Exposes Tomcat port |
| `mysql_data` | Stores database data permanently |
| `boutique-network` | Allows containers to communicate |
| `depends_on` | Starts MySQL before Tomcat |

Important: Inside the Docker network, the Tomcat application should connect to MySQL using hostname `mysql` and port `3306`, not `localhost`.

## 4. Scenario-based questions and answers

### Scenario 1: Configure port mappings and custom Docker network

Question: How do you configure port mappings and a custom Docker network?

Answer:

We configure port mappings and a custom bridge network in the Docker Compose YAML file.

yaml

```yaml
ports:
  - "8080:8080"
```

This allows users to access Tomcat through port 8080.

yaml

```yaml
ports:
  - "3306:3306"
```

This exposes MySQL through port 3306.

Create a custom network:

yaml

```yaml
networks:
  boutique-network:
    driver: bridge
```

Attach both containers to the network:

yaml

```yaml
networks:
  - boutique-network
```

Result:

- Tomcat is accessible at `http://localhost:8080`.
- MySQL is accessible on port `3306`.
- Tomcat communicates with MySQL using hostname `mysql`.
- Both containers communicate securely through the custom Docker network.

### Scenario 2: MySQL data is lost after removing the container

Question: Why does this happen, and how can you preserve database data?

Answer:

Data is lost because the database is stored inside the container's writable filesystem. When the container is removed, its internal data may also be deleted.

Solution: Use Docker volumes.

Add the following configuration:

yaml

```yaml
services:
  mysql:
    image: mysql:8.0
    volumes:
      - mysql_data:/var/lib/mysql

volumes:
  mysql_data:
```

Explanation:

- `mysql_data` creates a persistent Docker volume.
- `/var/lib/mysql` is the MySQL database storage directory.
- Database data remains محفوظ even if the MySQL container is removed and recreated.

To verify the volume:

bash

```bash
docker volume ls
```

To inspect the volume:

bash

```bash
docker volume inspect online-boutique_mysql_data
```

Result: Customer registration details and product information remain stored even after recreating the MySQL container, provided the volume is not deleted.

Step 6: Restart the containers

bash

```bash

```

Step 7: Stop containers safely

bash


## 5. Create Jenkins Scripted Pipeline

Open the Jenkins Pipeline job configuration.

Select Pipeline and choose Pipeline script.

Enter the following Scripted Pipeline code:

groovy

```groovy

node {
    stage('GitHub Clone') {
        git branch: 'main',
            url: 'https://github.com/haleema91/LAB-INTERNAL-II-OBS.git'
    }

    stage('Maven Clean') {
        sh 'mvn clean'
    }

    stage('Maven Build') {
        sh 'mvn compile'
    }

    stage('Maven Test') {
        sh 'mvn test'
    }

    stage('Maven Package') {
        sh 'mvn package'
    }

    stage('Deploy to Tomcat') {
        sh '''
        cp target/*.war /opt/tomcat/webapps/
        '''
    }
}
```

Note:

- Change the branch name if your repository uses a different default branch.
- Configure Jenkins permissions so the Jenkins user can access the Tomcat webapps directory.
- For a private repository, configure GitHub credentials in Jenkins and use `credentialsId` in the Git checkout.
- Ensure Maven and Java are installed on the Jenkins agent.

Click Save, then click Build Now to execute the pipeline manually for the first time.

Answer:

Provide the GitHub repository URL inside the `git` step of the Jenkins pipeline.

Example:

groovy

```groovy
git branch: 'main',
    credentialsId: 'github-credentials',
    url: 'https://github.com/haleema91/LAB-INTERNAL-II-OBS.git'
```

Explanation: The `url` parameter specifies the GitHub repository location, while `credentialsId` provides authentication for accessing the private repository.

3. Your Online Boutique Store application is building successfully, but the WAR file is not generated. Which Maven command should you execute in pipeline code?

Explanation: The `mvn package` command compiles, tests, and packages the application into a WAR file when the Maven project is configured with WAR packaging.
